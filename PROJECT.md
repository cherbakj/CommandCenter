# Command Center

Joe's local desktop hub. It pulls Outlook, Teams, Pulse tickets, Asana and SQL Server tools into
one window, sends alerts, and hosts Claude Code and VS Code for his projects. It runs on this PC
and for this Windows user only (127.0.0.1:8765 behind a per-launch session cookie). It lives in
`C:\Sonance\internal\CommandCenter`, next to Pulse, for corporate/VPN folder access.

## Start it
- Use the **Command Center** shortcut (desktop / Start menu), or `run.cmd`. It also starts at sign-in, minimized to the tray.
- Opens **borderless full screen** (`ui.start_fullscreen`). The header has Lock (🔒), Restart, Minimize, Full screen (F11) and **⏻ Power** (where the old ✕ close-to-tray was): a menu with Minimize, Windowed / Full screen, Restart Command Center and **Close Command Center**, a real exit after a confirm (`POST /api/app/quit`, the same as Quit in the tray: docked VS Code and SSMS go back to normal windows, never closed, and the next start docks VS Code again). The window is only ever open, minimized or closed (Joe's call 2026-10-27): the window's own close (Alt+F4) minimizes it, and nothing hides it to the tray any more. Alerts keep running while minimized.
- **Windows Hello / the Windows password** is asked when the window is first shown, in front of the start-up page: the launch animation's puzzle assembling ("SIGN IN"; `desktop._gate_page`, splash.js in gate mode, no API calls). Unlock / Minimize / Quit show only if Hello fails or is cancelled. There's no idle re-lock; **Lock** in the header logs out of Command Center and shows the padlock page.
- A puzzle-piece launch animation with live sync checks plays on each load; after the start-up page the dashboard opens at `/#signed-in` (`/auth?...&s=1`) and it starts assembled, straight to the sync checks. Turn it off under Profile (the start-up page still shows the puzzle: it can't read the Profile before sign-in).
- Commands: `run.cmd install|uninstall|serve|login <profile> <url>|setpass <connection>`. `serve` = server only, with a one-time browser sign-in link.
- **Dependencies:** `requirements.txt` pins the top-level packages; `requirements.lock` pins everything (pip freeze). Set up or repair `.venv` with `.venv\Scripts\python.exe -m pip install -r requirements.lock`. After an intended upgrade, regenerate it with `pip freeze` (keep its header) and update the pins in `requirements.txt`.

## Configure it
`config.yaml` (created from `config.example.yaml`; every setting is commented). Secrets are never in config: work secrets live in
Windows Credential Manager (services `CommandCenter-SQL`, `CommandCenter-Toolkit`, `CommandCenter-Pulse`, `CommandCenter-Asana`); personal ones in the personal vault.
Appearance (skin, colors, text size, density, effects: glow, frosted glass, background motion, dot grid, animations) lives in the in-app **Profile** (avatar at top right), stored in SQLite (DPAPI-encrypted with the name and initials).
- **Skin** (Profile > Skin): **Command Center** (the original glass and neon look, the default) or **Pulse**, which matches the Pulse site's dark theme (`static/skin-pulse.css`, on with `<html data-skin="pulse">`; its colors are Pulse's own tokens from pulse-nextjs `app/globals.css`): charcoal surfaces (#1a1f24 / #242a31 / #2d343c) with hairline borders, Montserrat for all text with tabular figures (JetBrains Mono only for paths, SQL and logs), Sonance blue (picking the skin also picks the **Sonance Blue** theme, #00a3e1 + #00b2a9, unless the colors are custom), Pulse's shared-nav header, underlined tabs, uppercase dim section labels, KPI-card stat tiles (label on top, the tile's color as a left rail), outline / solid-blue buttons, page-ground fields with a blue focus ring, card-colored dialogs and Pulse's blue scrollbars. It's flat like Pulse: glow, frosted glass, background motion and the dot grid are off (their switches are greyed while it's chosen and come back as they were on the Command Center skin) and nothing blinks. Element-level rules use `:where(...)` so a module's own button and field classes still apply. The last skin is kept per viewer in localStorage `cc-skin`, so a reload paints in it before the profile loads. The launch animation, lock and start-up pages keep the Command Center look.

## Layout of the window
- **Split workspace** (>= 1600px wide; toggle Split/Single in the header):
  - **COMMS** (left): Today, Alerts, Mail, Calendar, Teams, Pulse Feedback, Personal.
  - **WORK** (right): VS Code · Claude, Toolkit, SQL, Pulse, Websites. The **Working on:** project selector above them shows only while the VS Code tab is open (CSS `:has` in `vscode.css`, split and single layouts).
- **Focus layout** (header button "Pulse | Code", or Ctrl+K "Focus layout: Pulse + VS Code"): the Pulse site on the left, VS Code on the right; the header (nav, badges, status, clock) stays and keeps updating. The Pulse tab and its nav button move into COMMS while it's on (VS Code stays put: moving its iframe would reload it), so COMMS tabs replace Pulse on the left and WORK tabs replace VS Code on the right. Always two panes (the Split/Single toggle is hidden); in a window under 1600px it falls back to one pane at a time with Pulse under COMMS. Remembered in localStorage `cc.layout.focus` (with the tabs to go back to).
- **Splitter:** draggable and keyboard-movable; its position is saved per viewer in localStorage (`cc.layout.split`; the focus layout keeps its own, `cc.layout.focusSplit`, default 50/50).
- **Sizing:** layouts use container queries on the pane (not the window) and rem units scaled by Profile text size.
- **Front-end plug-ins:** feature modules register through `window.CC` (`CC.registerTab({id, label, render, onShow, pane})`, `CC.addPaletteSource`, `CC.activeProject`, events `cc:project` / `cc:layout`).

## Features
- **Today:**
  - **Top strip:** clock + weather in one compact panel (Lake Forest | San Clemente toggle; rain/humidity/wind and the hourly strip only where there's width) and the stat tiles. Tiles are clickable: they open the matching tab, Alerts or Pulse Feedback, and briefly highlight the rows the tile counts (opening collapsed follow-up sections; `spotlight()` in app.js); modules add their own through `CC.addStatTile(fn)` / `CC.statTile`.
  - **Main panel:** tabs **Today's Agenda / Tasks / Follow-ups**, each with its count (Tasks also "N high", Follow-ups "N urgent" in red, visible from any tab). ARIA tabs with arrow keys / Home / End; the tools next to the tabs follow the open tab and stay on the tabs' row: in a narrow head (split COMMS pane; container queries on `.tw-head`) the tabs tighten, "Today's Agenda" reads "Agenda" and Rescan becomes ↻. The tab Joe picks is remembered per viewer (localStorage `cc.today.tab`); with nothing remembered yet, Today opens on Follow-ups when something is urgent, else on the agenda. `CC.todayTab(name)` selects one.
  - **Agenda:** meetings with free slots between them (drag a task from the Tasks tab: hovering Today's Agenda opens it, drop on a slot to block time), Yesterday and Notes buttons (daily.js).
  - **Today's calendar** (`daycal.js`) beside the main panel on a wide pane, under it on a narrow one (it replaced the Recent alerts column; alerts are on the Alerts tab and the header badge): the day as a time grid (work hours at least, stretched to fit events; outside-work hours shaded), all-day items in a strip on top, a red line at the current time, overlapping events side by side. Same sources as the Calendar tab (`GET /api/planner?days=1`): Outlook meetings (click opens them in Outlook; Join on Teams meetings not yet over), overlay calendars in their colors and personal entries (click opens Personal; both only while the vault is unlocked and Privacy mode is off, else "Personal calendars locked" with Unlock). Fetched with Today's refreshes (at most once a minute), on a new day and on privacy changes; redrawn every minute. Calendar opens the 10-day view. On a tall window Today fills the pane and each panel scrolls inside itself.
  - The hotbar (launch buttons, Alt+1-9) and the Top 3 strip were removed.
- **Tasks:** Outlook / To Do and Asana tasks, sorted by **priority** (High / Normal / Low; the pill on each row opens a menu), then due date. Outlook tasks keep it in Outlook's own Importance (shows in Outlook and To Do), written through `outlook.set_task_priority` (`POST /api/tasks/priority`); Asana tasks keep it on this PC (kv `tasks:priority`, DPAPI-encrypted, Normal = no entry, pruned when the task is gone). New tasks start Normal; in quick capture a leading `!` makes a High task.
- **Follow-ups** (`today.py`, cached 2 min):
  - **Urgent:** reply needed from Joe's urgent people (edited in the app or `followups.urgent_people`).
  - **Needs your reply:** internal @sonance.com senders only, excluding auto-replies and sharing notices, and only when the email names Joe (`followups.mention_names`, his Outlook name or address) in the subject or the new text above the quoted history (`needs_reply_requires_mention`). Urgent people always count.
  - **Teams:** reply-needed from Teams missed-activity emails.
  - **Awaiting their reply:** sent mail with no answer yet.
  - **Flagged:** recent flags from people; flags set before `followups.flagged_since` (YYYY-MM-DD, by Outlook's flagged-on time, PidLidToDoOrdinalDate; received time when missing) are ignored everywhere in CC, including the Calendar (Outlook keeps them); automated NoReply@sonance.com flags are hidden. **Unflag** clears the Outlook flag ("Mark flag complete" is in the ⋯ menu); D in triage on a flagged email also clears its flag.
  - **Important senders:** unread mail from Joe's important senders (below; data key `unread_vip`).
  - **Actions:** Snooze, Dismiss, Mute, Mark urgent, Mark sender important. No-reply reminders, and urgent escalation after `urgent_escalate_hours`.
  - **Tools:** ▶ Triage, **Manage ▾** (a menu: Urgent people, Important senders, Snoozed / Watching, Muted senders; the buttons live in `#fu-manage` and modules add theirs there) and Rescan.
  - **Shown as a dense list:** a section per group (count, collapsible; remembered in `cc.today.fu.collapsed`), one row per item: source tag, who, subject, age (full time on hover), the main action (Reply / Open Teams / Nudge / View). Snooze, Dismiss and the second action (View, Done, Remind me) appear on hover or keyboard focus; Teams chat, Mark urgent, Mute and module actions (`CC.addMailAction(fn(mail, "followup"))`, e.g. Mark sender important, Spam) are in the row's ⋯ menu (role=menu, arrow keys, Esc). A ★ before the name marks an important sender.
- **Source tags:** every item shows where it came from (Outlook / Sent / Flagged / Teams / Calendar / To Do / Asana / Pulse / SQL / Website / Personal), with the sender address.
- **Overlay calendars (`feeds.py`):** read-only iCal feeds (Google Calendar "Secret address in iCal format", iCloud public calendar links; Skylight's source calendars), color-coded on the 10-day calendar with a legend to show/hide each. Manage via Calendar > Calendars.
  - Links live in the **personal vault**.
  - Hosts allowed: calendar.google.com, `*.google.com/calendar/` and `*.icloud.com` only. https only, global (public) addresses only (`is_global`), the connection goes to the address that was checked (no DNS rebinding; TLS still checks the name), no proxy, redirects re-checked, 10 MB cap.
  - Parsing is bounded: single events far from the window are dropped as text first, at most 5000 VEVENTs and 1000 events per calendar, SECONDLY/MINUTELY rules (and dense rules running since long ago) are skipped, 3 s budget per parse, one download + parse in flight per calendar.
  - Per-calendar detail level: full / titles (default) / busy. Fields are stripped before they're cached or returned.
  - Events are held in memory for 15 minutes, only while the vault is unlocked. Never written to Outlook or disk.
- **Lunch blocks (`outlook._is_lunch`):** a plain Outlook appointment (no attendees, not all day) whose whole subject is "Blocked" or "Lunch", inside 11:00-14:30 (`outlook.meetings.lunch: {subjects, between}`), comes back as subject "Lunch", `lunch: true`. It shows (🍽 Lunch in the agenda, a hatched block on Today's calendar, "Lunch" on the Calendar tab) and still fills its time for free slots, but it's not counted as a meeting (tiles, Agenda count, briefing, wrap-up), gets no 15 / 5 / now warnings, no "capture notes?" prompt and no Prep / Notes actions. Joe's recurring "Blocked" 12:00-1:30 is his lunch.
- **Calendar (`planner.py`, `planner.js`; the tab is planner.js's alone):**
  - Outlook meetings for the next 10 days, including all-day events.
  - Dated follow-ups: tasks, flags due, snoozes, reply checks.
  - **Personal entries**, kept in the personal vault (encrypted with Joe's own passphrase), never sent to Outlook.
- **Spam blocks (`spam.py`, `spam.js`):** Spam on an email from outside Sonance (Mail rows/reader, a follow-up row's ⋯ menu, X in triage) blocks the exact sender (default), the whole domain, or a subject phrase.
  - The dialog previews matching Inbox mail (`POST /api/spam/preview`, single-use, 5 min) and moves it to Junk Email only if ticked; Undo for 30 s. Manage under Mail > Spam blocks or Ctrl+K.
  - Enforced by two Outlook rules "Command Center spam blocks — senders / — subjects" (work with Command Center closed; other rules are never touched; checked every 6 h, Retry rebuilds) plus an app filter that hides blocked mail everywhere and moves new matches to Junk.
  - Refused: internal senders, Joe's own address, urgent people, whole-domain blocks on shared providers (`spam.shared_providers`), and short or generic phrases (`spam.subject_stoplist`). Blocks are DPAPI-encrypted (kv `spam:blocks`).
  - **Alerts:** a block deletes the feed's alerts (read or unread) for the email it started from, the matching Inbox mail the preview found, and other alerted emails that match it (looked up in Outlook, newest 300). Undo doesn't bring them back. Afterwards Mail, Today, the alert feed and the header badge refresh; the toast says how many alerts went.
- **Important senders (`people.py`, `important.js`):** new mail from them is a high-priority alert ("Important sender: <subject>"; toast "Outlook: important new mail"; after urgent people, before the other `outlook.rules`), their unread mail is the Follow-ups group "Important senders", and their mail shows a ★ (Mail rows, reader, follow-up rows; `important: true` from the server).
  - **List:** the senders of the sender-only, priority-high `outlook.rules` entries (the "VIP sender" rule; config.example.yaml's two placeholder examples are ignored) plus a list edited in the app (kv `people:important`, DPAPI-sealed, up to 200, kept until removed). Entries are an address or `@domain.com` (matches that domain exactly, not subdomains, like the rules). Whole domains are refused for internal domains and shared providers (`spam.shared_providers`).
  - **Marking:** ☆ on a Mail row (on hover) and "☆ Mark important" in the reader, "Mark sender important" in a follow-up row's ⋯ menu: one click adds the address; for an outside sender at a company domain it asks "This sender" or "Everyone @domain". On an important sender the same action removes the matching app entries (a config.yaml entry is explained, not removed). Teams' notification emails get no action.
  - **Manage:** Follow-ups > Manage ▾ > Important senders, or Ctrl+K "Important senders" (config.yaml entries shown read-only). `GET/POST /api/people/important` (POST `senders` replaces the list; `add` / `remove` change single entries); every change clears the follow-ups cache. Logs carry counts only.
- **Open in Outlook:** items open in an Outlook window brought in front of the full-screen app (`outlook._show`). View on a flagged/calendar item opens that email in the reader and pins it at the top of the Mail list.
- **Alerts:** toast + sound + feed (toasts say only "<Source>: <category>" unless `alerts.toast_detail: full`, because Windows keeps toast text unencrypted); focus mode (manual, tray, or calendar events containing "focus"); morning briefing and end-of-day wrap-up; meeting reminders at `outlook.meetings.remind_minutes` (default 15, 5 and 0 = "starts now", which still fires if a scan lands up to 2 minutes late; each once per meeting start) with Join and a **Prep** card (attendees, recent mail, open follow-ups). **Opening an alert marks it read:** any of its action buttons (View mail, Open Pulse, Join, Prep, Open chat...) marks it read on the spot, and reading an email anywhere in Command Center (the Mail reader, a follow-up's View, triage) marks the alerts for that email read (`db.mark_mail_alerts_read`; `POST /api/mail/read` and `/api/alerts/read-mail`). **Answering removes them:** a reply sent from Command Center (reply dialog or triage) deletes that email's alerts, read or not (`db.delete_mail_alerts`), and Teams alerts go once their chat is no longer unread (below).
- **Orders (`orders.py`):** copying an order number (7-10 digits) or opening an email that contains one looks it up with the saved SQL query `Find order` (needs SQL set up).
- **Claude = the VS Code tab** ("VS Code · Claude"). The old terminal Claude tab (`projects.js`, xterm, `static/vendor/`) is gone; `terminal.py` (ConPTY sessions, `/ws/claude`) stays loaded but no page uses it.
  - Projects come from `C:\Sonance\internal\*`, `~\source\*` and `projects.extra` (`projects.py`). The tab opens the **Working on:** project; **New window** starts Claude for it in Windows Terminal; Ctrl+K has "VS Code + Claude: <project>", "Claude (new window): <project>" and "New project…".
- **Docked desktop VS Code (`codedock.py`, `codedock.js`; the desktop app's VS Code tab):** the real desktop VS Code docked into the tab, like SSMS in the SQL tab, so **a Command Center restart doesn't end VS Code sessions** (Claude Code chats, terminals, unsaved editors).
  - **Open <project>** shows the WORKING ON project's VS Code window: one already docked, one already open as a normal window (found by its title naming the folder; it's docked), or VS Code opens the folder (`Code.exe <folder>`, list arguments, without Command Center's ELECTRON_* / VSCODE_* environment) and its window is docked when it appears (90 s). Same "other accounts can modify this folder" confirmation as everywhere.
  - Several windows can be docked (one per project, a button each in the bar); the WORKING ON project's shows and the others stay docked and running behind it. Changing WORKING ON shows that project's window, or opens it if VS Code is showing here. **Dock running VS Code** takes any VS Code window of yours; **Undock** gives the shown one back (nothing is closed). **New window** still starts Claude in Windows Terminal.
  - **Restart / Quit:** docked windows go back as normal windows (minimized on Restart, shown on Quit; never closed) and are recorded in kv `vscode:dock` (window handle, process id, folder; sealed); the next start docks the ones still open again once it's unlocked, with the same one showing, so the Claude Code chat in them carries on (tested: VS Code's processes, extension host included, are the same before and after). Later clean-up passes (window closing, exit hook) never overwrite the record. **Lock** does the same in memory. **Undock** takes a window off the record. After a reboot or a crash the recorded windows are gone and nothing is docked.
  - VS Code keeps a 7 px invisible border when docked: the window is placed that much outside the panel and the panel clips it. VS Code moving or sizing itself (F11, maximize) is fitted back to the stage. A new window of a docked VS Code (file dialog, message box, another VS Code window) is brought in front of Command Center; its other already-open windows are left alone.
  - Keys: a click inside the docked VS Code gives it the keyboard (as a child window it's never the active window, so it doesn't take the focus itself; the panel sees the click as `WM_PARENTNOTIFY` through a window subclass). While VS Code has the keyboard, Ctrl+K, Ctrl+Shift+P and F11 are VS Code's (no Privacy-mode hotkey is passed through, unlike SSMS); click Command Center's header for its own shortcuts.
  - Serve mode / a browser: nothing to dock; the tab is the web VS Code below.
- **VS Code tab, web version (`vscode.py`, `vscode.js`; serve mode / a browser):**
  - Runs the VS Code Server build matching desktop VS Code (bundled node, not `code serve-web`, which fails here).
  - Listens on 127.0.0.1 only, with a random port reused while free and a per-launch token passed over a named pipe.
  - **Mirror of desktop VS Code** (one way, before every start; **Sync from desktop** restarts to redo it; `vscode.mirror_desktop`):
    - Extensions listed in `~\.vscode\extensions\extensions.json` are copied (same versions) into `data/vscode/server/extensions` and registered in its `extensions.json`; first copy about 2 GB / 30 s. UI-only ones (e.g. tomoki1207.pdf) are skipped and listed on the tab. Copies of extensions removed from desktop are removed; others are never touched. A version web VS Code updated itself is kept.
    - `%APPDATA%\Code\User\settings.json` (minus `sync.*` / `settingsSync.*`) goes into the server's Machine settings (`data/vscode/server/data/Machine/settings.json`); keys mirrored before but gone from desktop are removed, keys set only in web VS Code stay. No `workbench.colorTheme` on desktop means desktop's default dark theme. Application-scope settings (which Machine settings can't carry) are moved into the page's own user settings by the helper extension.
    - Keybindings (not "-command" removals) and snippets become contributions of `commandcenter.cc-helper`, a small extension Command Center writes into `data/vscode/server/extensions` (no network; reads only its own files and the Machine settings). Profiles aren't mirrored.
    - Desktop files are only read. Setting values are never logged; the tab shows counts only. State: `data/vscode/server/cc-mirror.json` (key names and folders).
  - **Claude panel:** the helper shows Claude Code in the secondary side bar when the window opens (and once a folder is trusted; `commandCenter.showClaudeOnStart`). The tab's **Claude panel** button touches `open-claude.signal` in the helper's folder and the helper shows it again. Claude Code signs in from `~\.claude`, shared with desktop.
  - First time in a folder (per port), VS Code opens it in Restricted Mode: Manage > Trust, or Claude Code and most extensions stay off.
  - Known issue (before the mirror too): the integrated terminal's powershell.exe exits with 0xC0000022 (access denied) inside web VS Code.
  - Data in `data/vscode` (about 2.6 GB with the mirrored extensions).
- **Toolkit tab (`toolkit.py`):** Cherbak's Toolkit (Shipping, Logi, Customers) against SQL Server.
  - Every write is a single-row, whitelisted, parameterized transaction, confirmed in the UI with a before/after diff.
  - Every attempt is logged in SQLite `toolkit_changes`.
  - TLS verifies the server certificate by default; this PC trusts Sonance's corp CAs.
  - Servers with only SQL Server's self-signed certificate (snc-awsw-db01): Toolkit > Connection > Certificate pins its SHA-256 fingerprint (`connectors/sqlcert.py` reads it over a TDS PRELOGIN + TLS handshake, no login). Before every connection the certificate is read again; a different one stops the connection before the password is sent ("certificate changed", re-approve after a SQL service restart).
- **Pulse Feedback tab (COMMS; `pulse.py`, `pulse.js`):** read-only Postgres access to `public.data_reviews` through a least-privilege role `commandcenter_ro` (setup SQL on the tab, run by Joe in Supabase). Polls every 2 min for new or changed tickets on Joe (no alert when one moves to "Waiting on reporter", Joe's call 2026-10-27; it coming back to Open still alerts). TLS is `verify-full` against Supabase's root CA (`data/certs/supabase-prod-ca-2021.crt`); production project `ysogodjjjdomsfbpqbfb`. Ticket list with aging, filters and search; "Open in Pulse" (on a ticket row, and on Pulse alerts: action type `pulse`) opens the ticket in the WORK Pulse tab (`CC.pulseSite.open(url)`), or the default browser when there's no site view.
- **Pulse tab (WORK; `pulseview.js`, `siteview.PulseView`):** the real site with a **Prod | Dev** switch (`pulse.url` / `pulse.dev_url`), each keeping its own page and sign-in (Okta). Back / Forward / Reload / Home / Open in browser; the bar shows the page title and host/path. The sites refuse to be framed (`frame-ancestors 'self'`), so in the desktop app the window hosts a second WebView2 over the tab's stage (see Security model). In serve mode / a browser the tab offers "Open Pulse" / "Open Pulse Dev" in the default browser plus the aging summary.
- **Verified sending:** every reply is reviewed before it sends.
  - `POST /api/mail/reply/preview` builds the reply in Outlook, reads its recipients and subject, discards it, and issues a single-use `approval_id` (5 min).
  - `POST /api/mail/reply` with `send:true` needs that approval for the exact same text, and Outlook re-checks the recipients right before Send.
  - The UI (`CC.replyDialog`, triage) shows recipients, flagging anyone outside Sonance, then a deliberate Send click. Enter never sends; Ctrl+Enter only opens the review.
  - No recipients in the preview: no Send button, only "open a draft in Outlook". A failed send goes back to the text ("Not sent: <reason>"), so the next Review gets a fresh approval. Unsent text is kept per message in memory until it's sent or opened as a draft.
  - Sent replies are logged locally in kv `mail:sent_log` (subject and recipients only, no bodies), encrypted.
- **Workday (`daily.py`):** uncommitted/unpushed work reminder (an "Uncommitted projects" tile after `daily.uncommitted_after`), yesterday recap (commits, meetings, sent mail, tasks, Pulse closed; copy for stand-up), meeting notes + action items (→ To Do / Asana; "capture notes?" after each meeting). Notes are DPAPI-encrypted work data: shown in Privacy mode and labelled "encrypted", not "private". The Top 3 strip was removed (its old table `daily_top3` is dropped at start).
- **Off-hours work log (`offhours.py`, `offhours.js`):** time Joe is active at this PC outside work hours (`offhours:` in config: 08:00-17:00 Mon-Fri by default; weekends count all day).
  - **Counted:** Windows unlocked (`privacy.windows_locked`) with keyboard/mouse input (GetLastInputInfo), sampled every 60 s; the minute of the last input is active. Active minutes up to `offhours.idle_minutes` (10) apart merge into one session; a longer pause, or a sample that finds Windows locked, ends it. Only the parts outside work hours are stored, split at midnight.
  - **Shown:** an "Off-hours today" tile (today's time, this week's Mon-Sun total; pink with a dot while it's counting now); click (or Ctrl+K "Off-hours this week") for each day's sessions. `GET /api/offhours`.
  - **Gaps:** nothing is logged while Command Center isn't running (it starts at sign-in) or the PC sleeps. Input that software injects counts like real input.
  - **Stored:** table `offhours_log` (day, sealed JSON of [start, end] minutes): times only, never apps, windows or keys. Work data (DPAPI, shown in Privacy mode); the day is clear metadata; `retention.offhours_days` (400).
- **Triage (`triage.js`, Shift+T):** one-at-a-time queue with single-key actions; replies use the verified-send flow. An item cleared this session keeps Reply/Snooze/Done/Task off when revisited (a snooze can be undone).
- **Personal tab (`reminders.py`, `personal.js`):** the one place for personal items. Today's reminders as a checklist in time order (Done per day, Snooze while one is showing, next occurrence; overdue and not done is red), every reminder (On/Off, Edit, Delete), the next 7 days of personal calendar entries and personal entries saved in the last 14 days (quick-capture notes are personal entries), read from the planner's vault records, not copied. Locked vault / not set up / Privacy mode: only a Set up / Unlock / Show prompt (locked, not Privacy mode: how many reminders today and how many are done). Ctrl+K: "Personal", "Add personal reminder".
  - **Reminders:** text (200 chars), optional note, time of day, repeat Weekdays (the default) / Every day / chosen days / Once (a date), On/Off, Show Snooze (default on). A new reminder, or one whose time changed, never fires for a time already past.
  - **Pop-up:** at the time, one modal pop-up (its own `<dialog>`, so the Pulse view hides under it) lists every reminder that is due, each with **Done** and **Snooze** (one click = `personal.snooze_minutes`, default 15; ▾ for 5 / 30 / 60). No Dismiss: Esc, clicks outside and other code don't close it; another dialog can open over it and it is on top again when that closes. Done and snoozes are stored server-side, so after a reload or restart a not-done reminder shows again. A snoozed one comes back after the snooze. ## Security model (security.py, desktop.py)
- **Loopback and same user:** binds 127.0.0.1 with SO_EXCLUSIVEADDRUSE. Each connection is checked against the owning process's Windows user (always on; the result is cached per PID + process creation time, so a recycled PID is checked again).
- **Request checks:** Host check; `Sec-Fetch-Site` cross-site/same-site refused; non-GET requests need the `X-CommandCenter` header plus our Origin; WebSockets need our exact Origin.
- **Session cookie:** per-launch secret held in memory, set by a one-time `/auth?k=` bootstrap (HttpOnly, SameSite=Strict). Every route needs it.
- **Response headers:** strict CSP, `frame-ancestors 'self'`, nosniff, no-referrer, `no-store` (app files under `/static/`: `no-cache`, always revalidated). `index.html` is served with each `/static/` link stamped `?v=<file time>`, so after an update the window never runs a cached older script with the new page (that left `window.CC` undefined: no WORK tabs, no window buttons).
- **Window:** WebView2 with devtools, remote debugging, `file://` access, downloads, form autofill and password saving off (saved autofill data is cleared at each launch); no pywebview `js_api`. When a page's session ends (401), privacy.js removes personal items from the page.
- **Native windows over tabs (`overlay.py`, `nativestage.js`):** the Pulse and Teams site views and the docked SSMS are native windows inside the Command Center window, laid over a tab's empty stage.
  - **Placement channel:** no js_api. The dashboard POSTs `/api/window/<view>/bounds` (`pulse` / `teams` / `ssms`; normal session cookie + X-CommandCenter + Origin checks): page id, a sequence number (late reports, and any report from a page that has gone away, are dropped), the site (Pulse: Prod/Dev), visible, the stage rectangle in CSS px and up to 12 cut-outs. Throttled to one per 50 ms while moving (hiding is never held back), re-checked every second, and not sent at all without the desktop host. The server thread only stores the latest wish; one `BeginInvoke` at a time applies it on the UI thread (CSS px x DPI x dashboard zoom, clamped to the window).
  - **Hide rules:** a native window always paints above HTML, so the page hides it whenever Command Center UI must be on top: any `<dialog>` open (dialogs, triage, quick capture, Privacy/vault, Toolkit, reminders), the Ctrl+K palette, the launch splash, the restart overlay, `[aria-modal]`, another tab or sub-view, a hidden page. Toasts and other floating pieces (top-level fixed/absolute elements, popovers) over it cut a hole instead (window region), and hide it if they cover most of it. The host also hides them by itself on Lock and on any dashboard navigation (reload, lock page) until the new page reports, and moves keyboard focus back to the dashboard when a focused one hides or the quick-capture hotkey fires.
- **Site views (`siteview.py`: `PulseView`, `TeamsView`):** a WebView2 of their own (one per site, created when first shown) laid over the Pulse tab and the Teams tab. The rules below apply to both; each has its own allowlist.
  - **Isolation:** its own profile, `data/webview-pulse` / `data/webview-teams` (exclusive access; the site's cookies and sign-in never mix with Command Center's or each other's; the Teams view's profile isn't the background reader's `data/browser/teams`), and the site has no Command Center cookie, so it can't use the local API). Devtools, host objects, web messages, browser extensions, swipe navigation, status bar, autofill and password saving off (saved autofill cleared each launch); the OS-account SSO switch off for Pulse, on for Teams (`OS_SSO`: Microsoft's sign-in pages in that view get Joe's Windows work account without asking, as in Edge; top-level pages stay limited to the Teams allowlist). No script is injected into the site and nothing from it reaches Command Center except the host, path and title shown in the bar.
  - **Pulse allowlist (top-level pages):** https on 443, no `user:pass@`, hosts `pulse.sonance.com`, `dev.pulse.sonance.com` and `sonance.okta.com` (+ `pulse.view_sso_hosts`). Checked 2026-10: both sites 302 to `sonance.okta.com/oauth2/v1/authorize`, and Okta's IdP discovery (webfinger) for sonance.com answers type OKTA (no Microsoft hop); the sign-in page offers Okta FastPass. Other web pages and new-window requests open in the default browser; `mailto:`, `msteams:` and `com-okta-authenticator:` (FastPass) go to Windows; other schemes (and `file:`) are dropped. Only after a click (WebView2's `IsUserInitiated`): a page's script can't open tabs or launch apps by itself ("Blocked ..." in the bar); the exception is FastPass, which the Okta sign-in page launches from script after its own button, and only from `sonance.okta.com`. At most 3 links leave the view per 10 s. Frames inside allowed pages are the site's business (its CSP), except non-web schemes.
  - **Teams allowlist (top-level pages):** the same https rules, hosts `teams.microsoft.com`, `teams.cloud.microsoft`, `login.microsoftonline.com`, `login.microsoft.com` and `sonance.okta.com` (+ `teams.view_hosts`). Checked 2026-10 without signing in: Teams on the web sends the browser to `login.microsoftonline.com` (both the home page and a chat deep link reach it in the view, nothing blocked on the way); Microsoft's realm lookup for sonance.com (with a dummy address) answers "Federated" with `sonance.okta.com` (WS-Fed) as the sign-in page, which posts back to `login.microsoftonline.com`. `login.microsoft.com` and `teams.cloud.microsoft` are Microsoft's newer names for the same services. Same click-only / 3-per-10-s rules for anything leaving the view (an `msteams:` link from the page goes to the Teams app only after a click).
  - **Downloads:** only .csv .xlsx .pdf .docx .pptx .txt .json .png .jpg .jpeg .gif .webp (no legacy, macro-capable .xls: open one via Open in browser), into the Windows Downloads folder (others are cancelled with a note). "Save page as" (Ctrl+S) and screen capture are refused; all permission requests are denied except several downloads in a row: camera, microphone, notifications, location and clipboard read too (paste with Ctrl+V works without it; the Teams view says to use the Teams app when a call or meeting asks for the camera or microphone).
  - **Keys:** Ctrl+K inside the site opens Command Center's palette, Ctrl+Shift+P toggles Privacy mode, F11 full screen. Buttons use `/api/window/<view>/action` (navigate only to the site itself; Teams: `chat` takes a checked deep link, `app` opens the Teams app); `GET /api/window/<view>` gives the bar's state.
- **Docked VS Code (`codedock.CodeDock`):** only top-level VS Code main windows (class Chrome_WidgetWin_1, title ending "Visual Studio Code") of a `Code.exe` running as this Windows user whose image is the installed desktop VS Code (`vscode._desktop_install`, compared by real path), and that file must carry a valid Authenticode signature from Microsoft (checked before any open or dock). Folders open only if they're projects (`projects._known`, `check_safe`). Window handles shown to the page are re-checked on every action. Never closed or killed; Undock, Lock, Restart, Quit, the window being destroyed, Windows signing out and unhandled exceptions put the windows back. **Risk that can't be removed (as with SSMS):** if Command Center's process is killed outright, Windows destroys docked VS Code windows and VS Code closes them (tested: a one-window VS Code quit), so Claude chats running there stop; unsaved editors come back from VS Code's own backups. Prototype-tested at 100% display scaling (VS Code is per-monitor DPI aware, Command Center system-aware: a monitor at another scaling may size it oddly).
- **Docked SSMS (`ssmsdock.SsmsDock`):** SSMS's main window becomes a child of a panel in this window (caption/frame styles stripped, `SetParent`), placed and hidden like the site views.
  - **What it touches:** only the main window of an `Ssms.exe` process that runs as this Windows user (process token SID) and whose image is the installed SSMS (`sql.ssms_path`, default the SSMS 20 path; compared by real path), and that file must carry a valid Authenticode signature from Microsoft (checked before any start or dock). Other processes, other users' SSMS and pids not in that list are refused. A started SSMS runs in its own process group, outside any job of Command Center's.
  - **Never closed or killed.** Undock, Lock (undocked and minimized; docked again after unlock), Quit, Restart, the window being destroyed (the panel's HandleDestroyed runs before its children are destroyed), Windows ending the session, and unhandled Python/.NET exceptions put SSMS back as a normal window with its own styles and placement.
  - **Risk that can't be removed:** if Command Center's process is killed outright (Task Manager, a hard crash), Windows destroys its windows' children, including a docked SSMS main window, and SSMS then exits (tested: killing a test copy with SSMS docked left neither the window nor the process). Unsaved query text survives only in SSMS's AutoRecover (Tools > Options > Environment > AutoRecover; keep it on, e.g. every 1-5 min). Save often while docked, or Undock for long sessions.
  - **Input:** a cross-process child shares input processing with this window, so an SSMS that stops responding can make Command Center slow to respond until it recovers (the bar says so; Undock ends it). While SSMS has the keyboard, Ctrl+K and F11 stay SSMS's (it uses Ctrl+K chords); Ctrl+Shift+P (Privacy mode) is passed to Command Center through a hotkey registered only while the keyboard is inside the docked SSMS.
  - **DPI:** SSMS 20 and Command Center are both system-DPI-aware, so they scale alike; tested at 100% and 125% dashboard zoom.
- **App folder:** ACL limited to Joe, SYSTEM and Administrators, enforced at start. The folders above it (up to the drive root) are checked read-only at start; if another account can write, delete or re-permission one, a high-priority Security alert gives the `icacls ... /inheritance:r /grant:r` fix, and `GET /api/status` reports `folder_security`.
- **Project folders:** a project that other accounts can modify (folder, `.claude`, `.git`, settings/hook files) is flagged `writable_by_others` in `/api/projects` and shown in red; starting Claude (embedded or New window) or opening it in VS Code needs an explicit confirmation, sent as `allow_unsafe` / `unsafe=1`. Folders with `;` or `"` in the path are never listed. Git runs with fsmonitor, hooks, untracked cache, signature verification (`log.showSignature`, `gpg.*program`), pager, external diff and `core.sshCommand` neutralized (`projects.GIT_SAFE`; every `git log` gets `--no-show-signature`). A repo whose own config sets a program or include key (`gpg.*`, `log.showSignature`, `include*`, `core.sshCommand`, `diff.external`, textconv, credential helpers, filters, pager...) isn't run through git at all (`projects.RISKY_CONFIG`; only its config is read).
- **VS Code server:** archive paths must stay inside the build folder; node.exe and every .exe/.node/.dll must be validly Authenticode-signed (Microsoft; GitHub, Inc. for its bundled tools) before the server starts. Mirrored extensions are outside that check: they're copied only from real folders (no links) directly in `~\.vscode\extensions` whose package.json matches the id/version desktop VS Code recorded, and only extensions desktop installed from the Marketplace (`metadata.source == "gallery"`, which checked their signatures; .vsix installs are skipped), so they're trusted as much as desktop VS Code trusts them. Copies never follow links. Folder names read back from the server's own extensions.json are checked to be plain names directly in its extensions folder before anything is removed, and nothing is removed when desktop's extension list is missing or empty. Desktop settings whose names (or fields inside them) look like passwords, tokens, keys or credentials aren't copied.
- **Lock screen:** its Quit/Hide/Unlock links work only while the lock page is showing.
- **Personal vault (`vault.py`, `privacy.py`):** personal data (entries, calendar links, quick-capture notes) is encrypted with AES-256-GCM, using a key derived from Joe's own passphrase (scrypt n=2^17). The passphrase is never stored, and it is not tied to company/domain accounts: DPAPI is avoided here because domain backup keys can recover it.
  - The key lives in memory only. Unlock is rate-limited and the counter persists.
  - **Unlocked for the day** (`privacy.stay_unlocked_today`, default on): once unlocked it stays unlocked until midnight, through Windows lock / session switch, sleep / hibernate and Command Center's Lock (getting back into Command Center still takes Windows Hello). It locks at midnight (`vault.unlocked_day`), with Lock vault, in Privacy mode (Ctrl+Shift+P, eye icon) and on restart. Trade-off: the key stays in memory meanwhile, and in the hibernation file if Windows hibernates. With the setting off, the old rules apply: it also locks on Command Center Lock, Windows lock / session switch (`lock_on_windows_lock`) and sleep / hibernate (power notification, plus a clock-gap check on resume). No idle auto-lock unless `privacy.auto_lock_minutes` is set (default 0).
  - A lock or Privacy mode during an unlock (while scrypt runs) wins: the new key is discarded. Unlocking turns off only a Privacy mode that was already on when the unlock started.
  - Changing the passphrase re-encrypts under the same locks as every write, and stops (changing nothing) if a record can't be decrypted. Derived key bytes are wiped once the AES-GCM object exists (best effort).
  - The Privacy & Data panel lists every source (Work/Personal) with what's stored, how it's protected and how long it's kept.
  - Forgotten passphrase: "Delete all personal data" is the only option.
  - **Personal reminders:** the reminder (text, note, time, repeat) is a vault record. So they can pop up while the vault is locked, a schedule-only copy (record id, time, repeat days / date, on/off, snooze allowed, created-since) and the firing state (days done / fired, open pop-ups, snooze ends) are kept as DPAPI-sealed work data (kv `reminders:schedule`, `reminders:state`): times and ids, never text. That copy is rebuilt from the vault on every unlock and when the Personal tab loads. Vault locks (Lock, Windows lock, sleep, Privacy mode, restart) don't touch it; "Delete all personal data" deletes it. Logs carry counts and short id prefixes only.
- **Work data at rest (`db.py`):** alert text, the sent log, follow-up subjects/names, settings with names (including the Profile), and the Toolkit change log (pk, before, after, error) are DPAPI-encrypted (`ccsealed:v1:`). A startup + daily migration encrypts any plaintext. The connection uses `secure_delete=ON` with regular VACUUM. Sealing, VACUUM and moves of old copies run with the rollback journal in PERSIST mode, and the journal is overwritten with zeros afterwards (it holds the old plaintext pages; `db.scrubbed_journal`). Pulse ticket state is sealed too. What stays in clear (dates, ids, counts) is listed in Privacy & Data under "Unencrypted metadata".
- **Retention (`retention:` in config):** alerts 30 days, sent log 90, Toolkit change log 365, `seen` 30, dismissed follow-ups 60, off-hours log 400, personal reminders' done / fired days 30 (`reminders_done_days`).
- **Secrets:** only in Credential Manager, the personal vault or memory. Logs, the database and API responses were swept for secrets.
  Logi passwords never come back in lists (`has_password` only); one user's password is fetched on an explicit Show/Clipboard click (POST `/api/toolkit/logi/password`), logged as a `reveal` in `toolkit_changes` without the value. New Logi passwords: 16 random characters (crypto.getRandomValues), upper/lower/digit/symbol, no look-alikes.
- **Log:** `data/commandcenter.log`, rotated at 5 MB (3 old files). Alerts are logged by id, source and priority only, never titles or bodies. Request errors are logged as type, path and code locations only, never the exception message (it can quote row values). At startup, older lines carrying work data are rewritten as `[redacted]`.
- **Fonts and network:** fonts are self-hosted (`static/fonts`: Inter for text, Orbitron for headings and numbers, JetBrains Mono for code, Montserrat for the Pulse skin; all SIL OFL; CSP `font-src 'self'`). The page makes no requests beyond 127.0.0.1.
- **Dev bypass:** `CC_DEV_NO_AUTH=1` works in `serve` mode only and logs a warning.

## Code layout
- `commandcenter/app.py`: core routes. Auto-loads the feature modules security, toolkit, pulse, terminal, vscode, planner, profile, feeds, daily, vault, privacy, spam, offhours, reminders and snip (each exposes `router` and optionally `background`).
- `commandcenter/overlay.py` (native windows over tabs), `siteview.py` (the Pulse and Teams site views) and `ssmsdock.py` (the SQL tab's SSMS dock) and `codedock.py` (the VS Code tab's desktop VS Code dock), used by `desktop.py`.
- `commandcenter/connectors/`: outlook, web, sql, sqlcert, asana, weather, teams. `people.py` handles internal domains, urgent people and important senders.
- `commandcenter/static/`:
  - Core UI: `app.js`, `style.css`, `index.html` (+ `teams.css` for the Teams tab; its code is the "teams" section of `app.js`).
  - Feature modules: `vscode`, `toolkit`, `pulse` (+ `pulseview.js`), `teamsview.js` (Teams on the web; its CSS is in `teams.css`), `ssms` (SQL tab), `codedock` (docked desktop VS Code), `nativestage.js` (stage reports for native windows), `planner`, `daycal` (Today's calendar), `profile`, `splash`, `daily`, `triage`, `capture`, `privacy`, `spam`, `important` (important senders), `offhours`, `personal` (`.js`/`.css`), `snip` (`.js`), `skin-pulse.css` (Profile > Skin > Pulse).
  - Shared assets: `jc-logo.svg` and `icon.ico` (the JC monogram).
- `data/` (git-ignored, private ACL): the SQLite DB, log, browser profiles, `vscode/`, and the ACL backup.

## Constraints
- Cylance blocks `.ps1` files, so never create them. Run everything through `run.cmd` or `.venv\Scripts\python.exe`.
- **Window from other threads:** never set a .NET property of the window (e.g. pywebview's `window.on_top`, which sets `TopMost` on the calling thread) from the server, tray or any non-UI thread. pythonnet keeps the GIL through a property set, and a property that sends the window a message waits for the UI thread, which may be waiting for the GIL: the whole app freezes (Windows "not responding"; it happened on 10/25-10/28 when a second launch or the tray showed CC). Use pywebview's methods (they `Invoke`, and pythonnet releases the GIL for method calls) or ctypes (`DesktopApp.show` brings the window forward with `SetWindowPos` through ctypes). Endpoints that wait on the window run in `asyncio.to_thread`.
- **Outlook COM** calls must stay on one thread (`outlook.call()`). Use `_table_rows()`/`_mail_rows()` for bulk reads; the To-Do folder ignores GetTable filters.
- **Tests:** run a second copy with `CC_PORT=<port> CC_DEV_NO_AUTH=1 python -m commandcenter serve --no-browser`. Never use 8765 for tests.

## Repo guard (protects shared repos such as Pulse)
`tools/repo-guard/` holds local-only git hooks, installed in `C:\Sonance\internal\Pulse\pulse-nextjs\.git\hooks` (which covers its worktrees).
They block commits and pushes that would carry Command Center details (paths, names, cookie and keyring names), JWTs or private keys,
or local-only files (`.env`, `.vscode/`, `.claude/settings.local.json`, `*.dpapi`). Hooks live in `.git` and are never pushed.
Command Center's own repo has no remote. To guard another repo, copy `guard.sh` to `<repo>/.git/hooks/command-center-guard.sh` along with `pre-commit` and `pre-push`.
